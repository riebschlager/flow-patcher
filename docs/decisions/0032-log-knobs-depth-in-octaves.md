# 0032 · Log-scaled knobs, with cable depth in octaves

Status: Accepted · 2026-10-25

## Context
Every number param was linear: its knob crossed the range in equal steps, and a cable into it added depth × signal in the param's unit (design.md, Core concepts). Filter's cutoff runs from 20 Hz to 20 kHz, so the bottom three octaves sat in the first 1 % of the knob, and a sweep's depth in Hz meant a different musical distance at every base: +600 Hz is more than an octave from 400 Hz and a quarter-tone from 10 kHz (#104). Delay time and Reverb params (#81) have the same shape. Chris decided on 2026-10-24 that depth on a log param is in octaves.

## Decision
- **A param-spec option.** `NumberParamSpec.scale: 'log'` (default `'linear'`) marks a number param whose knob reads its range by ratio. It needs 0 < min < max: `paramSpecError` says so, the compiler rejects a patch with a node whose definition breaks it, and the catalog test checks every node.
- **Natural units everywhere but the knob's travel.** The stored value, the typed value, the readout and what `param()` gives the node stay in the param's unit (Hz, s). Only the knob position is logarithmic: `knobPosition(spec, value)` and `knobValue(spec, position)`, exported from the engine for the editor, map value ⇄ 0–1, linear for a linear param. Out-of-range input gives the nearest end, NaN the default.
- **Depth in octaves.** On a log param, cables scale the base: value = base × 2^(Σ depth × signal), clamped to the range (`modulate`). A cable of depth 1 carrying 1 is one octave up; −1 is one down. Non-finite terms count as 0, as on linear params. A sum that isn't finite keeps the base; a finite sum whose power over- or underflows clamps to max or min. Linear params are unchanged, bit for bit. The editor's depth control reads "oct" and reaches ±log2(max / min) (`depthRange`, `depthUnit`).
- **Still deterministic.** `param()` stays a pure function of the base, the cables' signals at t and the channel, so window independence (ADR 0008) holds with no other change.
- **Ramps stay linear in Hz.** `paramAutomation` samples `param()` on the 60 Hz grid (ADR 0031), so a modulated log param follows its exponential course through linear ramps between grid points. Over 1/60 s the chord is within a fraction of a percent of the curve for any sweep a person would play (a two-octave-per-second sweep: under 0.02 %). A knob edit on an uncabled log param ramps linearly in Hz over 20 ms (`editRamp`), as on a linear param: the ramp is too short to hear its shape, and `exponentialRampToValueAtTime` is a new kind of automation to prove in both Web Audio implementations for no audible gain (ADR 0031 chose linear ramps for that reason).

## Consequences
- Filter's cutoff is log-scaled (Filter version 2), and so is Sampled Voice's (version 2; no example cables into it). The three examples that cable into Filter's cutoff now give depths in octaves: filter-sweep 3.17 (300 Hz × 9, the old 300–2700 Hz), wheel-scroll 0.5 (half an octave a wheel notch), touch-size 0.07 a pixel of contact width. filter-sweep's sweep is now exponential in Hz: equal time per octave.
- touch-size's depth matches the old 40 Hz a pixel at a 25 px fingertip (1.35 kHz against 1.4 kHz) but doubles the cutoff every 14 px where the old one added a constant: 18–40 px fingers give about 960 Hz–2.8 kHz (was 1.1–2 kHz), a 50 px contact 4.5 kHz, and about 80 px (a flat thumb or palm) reaches 20 kHz. Kept: the fingertip sizes it is played with stay between 1 and 3 kHz, and a wider contact opening the filter by octaves is the gesture the patch is about; a patch that wants a gentler curve sets a smaller depth.
- A cable into a log param is relative to the knob, so a Signal carrying Hz (a Map Range onto 650–15,600) no longer sets the cutoff: it would be read as octaves. Curve's exponential shape followed by Map Range into a linear param is still how to make an absolute exponential response; into a log param, a 0–1 Signal with depth log2(hi / lo) on a base of lo does it directly (Flow's Paint cutoff, 650 · 24^u, is base 650, depth 4.58).
- Open: a cable's depth keeps its number when the param it feeds changes scale. Before M4 the examples are edited by hand; from M4 on, a node that changes a param's scale needs a migration that rewrites the depth of every cable into it (ADR 0015), which can only approximate a Hz depth in octaves at one base.
